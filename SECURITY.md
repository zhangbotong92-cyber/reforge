# Security policy

## Supported versions

The published branch (`main`) only. Fixes land there and nowhere else.

## Reporting a vulnerability

Open a **draft security advisory** via
[Security → Advisories](https://github.com/zhangbotong92-cyber/reforge/security/advisories/new),
or email the maintainer if that is unavailable. Do not open a public issue with the details.

Please include: affected version/commit, a reproducer (fixture file if the bug is in a
parser), and the impact you believe it has. Expect a first reply within a week.

## What counts as in scope

REFORGE parses untrusted files and drives external processes. The interesting classes:

| Class | Example |
|---|---|
| Parser memory/DoS | a 2 GB PNG chunk length, a zlib bomb in `zTXt`, a cyclic ComfyUI graph, an MP4 with a box size of 1 |
| Path handling | a recipe `path` that escapes the working directory when a worker follows `plan()` |
| Command injection | the `REFORGE_CTL_<KIND>` or generator template evaluating a file name as shell syntax |
| Secret leakage | anything that writes an API key or a token into a recipe, a sidecar, or an embedded `iTXt` chunk |
| SSRF | a provider `base_url` that reaches link-local or metadata addresses |

## What does not count

- A captioner producing a wrong description. That is a quality bug, not a vulnerability.
- A recipe that reproduces an image you did not want reproduced. See the README's fidelity
  ladder — L1 is a caption, it is supposed to be approximate.
- Anything requiring an attacker to already control the user's machine.

## Our own hygiene rules

- No token, key, or credential may ever appear in a tracked file. The publish flow scrubs
  the token from `.git/config` and CI is expected to fail loudly on a `gh[op]_` string.
- `tests/` may contain only synthetic fixtures generated by `examples/make_sample.py` —
  never a real user's photo or prompt.
